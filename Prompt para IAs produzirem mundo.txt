Você é um gerador de conteúdo para um jogo de terror textual chamado "Centelha". Sua tarefa é gerar um JSON com plano, salas e cenas (dilemas) para uma zona de 10 salas.

---

TEMA E ATMOSFERA
Ambientação: [INSIRA AQUI O TEMA, EX: "Sanatório psiquiátrico abandonado nos anos 1980"]
Tom: [INSIRA AQUI O TOM, EX: "Terror clínico e visceral — horror concreto, com sangue, ferrugem, cheiro de desinfetante, eletrochoques"]
Lore central: [INSIRA AQUI A LORE, EX: "Pacientes desaparecem e os funcionários fingem que nada aconteceu"]

---

REGRAS DE TOPOLOGIA (PLANO)
1. Sala 1 = entrada. Sala 10 = fronteira (com "para_proxima_zona": true).
2. Cada sala tem de 1 a 3 saídas. Pelo menos uma sala tem 3+ (hub).
3. Toda conexão de ida (A → B) tem uma de volta (B → A) com ação inversa (ex: "Subir" ↔ "Descer").
4. A estrutura é uma árvore, sem ciclos.

---

REGRAS DE PROSA PARA "texto_logico"
5. Sala 1: descrição direta, sem "Depois de" ou "Ao avançar".
6. Salas 2–9: primeira frase começa com "Depois de [ação EXATA que levou a esta sala], você...".
7. Sala 10: se tiver múltiplas entradas, use "Ao avançar para este local, você...".
8. PROIBIDO como primeira frase: "Você se encontra", "Você está", "Você nota".
9. PROIBIDO repetir na primeira frase palavras da ação de chegada (entry-point leak).
10. Todo elemento físico citado nas "opcoes" de saída DEVE estar visivelmente descrito no texto — nunca crie uma opção sem âncora visual no texto.
11. Cada "texto_logico" precisa ter: (a) 3+ elementos do cenário, (b) 1+ dado sensorial (cheiro, som, temperatura, textura, luz, umidade), (c) uma âncora visual por saída, integrada à descrição do ambiente — nunca liste os caminhos como "você pode escolher entre X ou Y".

---

REGRAS PARA CENAS E DILEMAS (ARQUITETO DE CENAS)

Selecione aleatoriamente 2 a 3 salas entre 2 e 9 para receber uma cena. As demais não têm cena.

Para cada sala escolhida, sorteie um TIPO:
- **FÍSICO**: entidade/criatura ameaçadora presente na sala; o dilema gira em luta, fuga ou evasão.
- **MORAL/EXISTENCIAL**: uma pessoa, objeto, documento ou situação que força uma escolha de valor, sacrifício ou dúvida sobre si mesmo — sem exigir uma criatura atacando.

**No máximo 1 das cenas da zona pode ser FÍSICO.** As demais devem ser MORAL/EXISTENCIAL. (Isso é deliberado: cenas de perseguição são fáceis de gerar e tendem a dominar se não forem limitadas.)

1. **"texto_evento"** (3–4 frases): o elemento central deve parecer que sempre esteve ali, esperando.
   - FÍSICO: descreva a entidade com foco na ameaça.
   - MORAL/EXISTENCIAL: não precisa haver hostilidade — pode ser um pedido, uma descoberta, um vestígio que implica o jogador em algo.

2. **"dilemas"**: exatamente 1 dilema-pai com "ramificacoes" (array de 2–3 objetos, bifurcação genuína); os demais dilemas da cena (se houver) com "ramificacoes": null.
   - `resultado_texto` do pai: 2–3 frases, tensão aberta, `"dano": 0`. `destino_id` só é não-null se a ação cruzar um limiar físico (fuga, avanço, entrada) e deve existir nas saídas da sala.

3. Cada ramificação tem um **CUSTO**, de um destes dois tipos — nunca misture os dois numa mesma ramificação:
   - **a) Custo físico** (`dano` > 0): 1 frase visceral e específica sobre o ferimento. Gravidade: 1–4 leve, 5–9 severo, 10–20 brutal. Proibido escrever "perde X de energia" — descreva a lesão.
   - **b) Custo moral** (`"dano": 0`, mas irreversível): nomeie concretamente o que se perde — alguém que fica pra trás, uma vantagem sacrificada, uma mentira que passa a sustentar, um limite cruzado sem volta. Proibidas frases genéricas ("você sente que perdeu algo").

   - Em cenas **FÍSICO**: pelo menos 1 ramificação com custo físico alto (10–20).
   - Em cenas **MORAL/EXISTENCIAL**: pelo menos 1 ramificação com custo moral de alta gravidade (perda irreversível e concreta). Nenhuma ramificação dessas cenas precisa ter `dano` > 0.

**Proibições:** opções sem `destino_id` usando verbos de locomoção (sair, subir, atravessar); `resultado_texto` do pai descrevendo ação que o jogador não executou na `opcao_texto`; cenas MORAL/EXISTENCIAL onde toda ramificação termina em confronto físico.

---

ESTRUTURA EXATA DO JSON

```json
{
  "plano": {
    "1": {
      "local_fisico": "Nome da sala",
      "saidas": [
        {"destino": 2, "acao": "Ação de movimento (ex: Subir a escada de madeira)"},
        {"destino": 3, "acao": "Outra ação"}
      ]
    },
    "10": {
      "local_fisico": "Nome da fronteira",
      "saidas": [{"destino": 11, "acao": "Ação para a próxima zona"}],
      "para_proxima_zona": true
    }
  },
  "salas": {
    "1": { "texto_logico": "Descrição direta do ambiente (sem âncora)." },
    "10": { "texto_logico": "Ao avançar para este local, você [...]." }
  },
  "cenas": [
    {
      "sala_id": 7,
      "titulo": "Título da cena",
      "texto_evento": "Evento situacional (3–4 frases).",
      "dilemas": [
        {
          "opcao_texto": "...",
          "resultado_texto": "...",
          "dano": 0,
          "destino_id": null,
          "ramificacoes": [
            {"opcao_texto": "...", "resultado_texto": "...", "dano": 0, "destino_id": null},
            {"opcao_texto": "...", "resultado_texto": "...", "dano": 14, "destino_id": null}
          ]
        }
      ]
    }
  ]
}
```

- `cenas` contém apenas as 2–3 salas escolhidas. As demais não têm entrada.
- `dilemas` é sempre um array, mesmo com um único objeto (o pai).
- Todo `destino_id` usado existe nas `saidas` da sala, ou é `null`.
- `dano` é sempre inteiro entre 0 e 20.

---

IMPORTANTE
- Entregue APENAS o JSON, sem texto adicional, sem erros de sintaxe.
- Ações de ida e volta simétricas (ex: "Subir" ↔ "Descer").
- `texto_logico` e `texto_evento` são complementares, sem repetir informação física.
- A seleção de salas para cenas é aleatória (2 a 3, entre 2 e 9); o tipo de cada cena (FÍSICO/MORAL) também é sorteado, respeitando o limite de no máximo 1 FÍSICO por zona.

Agora, gere o JSON completo para 10 salas.
